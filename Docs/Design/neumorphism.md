# LinkX 新拟物（Neumorphism / Soft UI）设计规格 v1

> ⚠️ **本文件已作废，仅作技术记录。** 新拟物方向在 0.4.0 落地并真机验收后被用户（产品负责人）
> 于 2026-09-28 决定**回退**：实测空闲内存 +25%（27.1→33.5MB）、带动画页面 CPU +55%，
> 而视觉收益不足以在交付窗口内承担这个成本。交付版 UI 是回退后的平面版
> （那一版的完整代码留在维护者的离线备份里，本仓库只保留结论与下面这些仍然有效的技术记录）。
> 下面引用的 `Platforms/Windows/src/softui.rs` 与 `Platforms/Android/.../ui/Neu.kt` **已不存在**。
> 仍然有效的部分：§6.1 的 GDI 真高斯做法与四个坑、§6.3 的图标体系规则、§7 的自检清单——
> 图标几何现在由 `Platforms/Windows/src/icons.rs`（自采样折线路径引擎）与
> `Platforms/Android/app/src/main/res/drawable/ic_*.xml` 双端同坐标承载。

> 适用范围：Windows 自绘壳（Win32 + GDI）与 Android Compose 壳。两端**共用同一套 token 与图标几何**，
> 差异只允许出现在"同一 token 在各自渲染栈上怎么实现"这一层。
> 风格硬约束来自用户提供的 `neumorphism-hard-prompt.md`；本文件是它在 LinkX 上的**可执行化**，
> 并记录两处与原始提示词的有意偏离（见 §1.4）。

## 0. 为什么这个风格配 LinkX

LinkX 做的事是"同一张桌面上，手机和电脑之间把东西推过去"。它的核心状态全是**物理隐喻**：
接通 / 断开、推送 / 接收、通道宽窄。新拟物的语言恰好是"一块可以按下去的黏土表面"——
**凸起 = 可操作，凹陷 = 已接通/正在输入/已按下**。所以在这里光影不是装饰，是状态编码：
用户不需要读文字，看表面是鼓还是凹就知道这条链路通没通。

这也决定了本套设计的唯一"标志元素"：**链路槽**（§5）。

### 1.3 三档主题

`跟随系统 / 浅色 / 深色` 全部保留。跟随系统时：Windows 读 `AppsUseLightTheme`，
Android 读 `isSystemInDarkTheme()`。**新增单测锁死对比度**（见 §7），改色必须连带更新期望值。

### 1.4 与原始提示词的两处有意偏离（已判定，不再讨论）

1. **`text.secondary` 不用 `#6b7280`**。它在 `#e0e5ec` 上只有 **3.82:1**，达不到 WCAG AA 的 4.5:1，
   而提示词自己的交付清单里就要求"正文对比度满足 WCAG AA"。两条规则冲突时取无障碍那条，
   压深到 `#5b6472`（4.73）。
2. **深色主题保留**。提示词要求"只用浅色背景"，但深色是真实用户诉求且已上线；
   处理方式是保留其**物理规则**（双光源、同色系、无纯黑、低对比）而非保留其**色值**。

### 1.5 禁止（照抄提示词，两端一致）

纯黑/纯白背景 · 高对比配色 · `border` ≥2px · 渐变背景 · 直角 · 按钮 translate 位移 ·
hover 放大阴影 · 打破"左上亮 / 右下暗"的光源方向 · 硬边阴影（`0` 模糊半径）。

## 2. 阴影与圆角

光源固定在左上（浅色：亮边左上 / 暗边右下；暗色黏土同方向）。
下表是**两端实测值**（真机调过，别再改回"提示词里的 4/8"——那组在 440dpi 手机上糊成一团）。

| 语义 | Windows `softui::Shadow`（偏移/盒模糊半径） | Android `Neu.Depth`（偏移/扩散 dp） | 用于 |
|---|---|---|---|
| `sm` | `2 / 2` | `2 / 5` | 导航项、分段控件、开关钮、进度条填充 |
| `md` | `3 / 3` | `3 / 7` | 按钮、列表行、凸台、通知卡 |
| `lg` | `5 / 4` | `5 / 10` | 卡片、弹窗、链路槽底板 |

> Windows 侧 3 次盒模糊的**实际支撑**≈ `3×blur`（近似 σ=blur 的高斯），
> 所以 4 对应安卓端 10–12dp 的视觉扩散，两端是同一档。

圆角：`r.xs=10`（小标签）· `r.sm=14`（按钮/输入框）· `r.md=18`（行、导航项）· `r.lg=24`（卡片/弹窗）· `r.pill=高度/2`（开关、状态胶囊、链路槽凹槽）。
**同一屏内圆角只允许出现相邻两档**，否则读起来像拼的。

**凹陷（sink）不是"外阴影取反"**：本体先铺贴底色（`flush = mix(base, shadow_dark, 0.18)`），
再把两束光**裁进内壁**——朝光的左上内壁压暗、背光的右下内壁提亮。
方向画反（暗边跑到右下外）就不是"挖了个槽"而是"贴了块脏板"。

## 3. 交互状态（Extrude → Intrude）

| 元素 | Default | Hover | Active / 选中 | Focus | Disabled |
|---|---|---|---|---|---|
| 按钮 | `raise.md` | **`raise.sm`**（阴影缩小=手指遮光） | `sink.sm`（凹陷） | 外圈 `accent` 2px 柔光环 | `opacity .5`，阴影降一档 |
| 开关 | 轨道 `sink.md` + 钮 `raise.sm` | 钮 `raise.xs` | 轨道不变、钮滑到另一端并转 `raise.sm`，芯色 `accent` | 同按钮 | 灰化 |
| 输入框 | `sink.sm` | — | `sink` 深度**减小**（inset 6→2，"通道打开"） | 同 Active | 灰化 |
| 导航项 | `raise.sm`（可以按下去） | 阴影缩小 | `sink.md` + `accent.text` 文字 + 左侧凸点（**已在其中**） | 同按钮 | — |
| 列表行 | `raise.sm` | `raise.sm`→`raise.md` 反向：**hover 阴影变小** | `sink.sm` | — | — |

动效：统一 **300ms ease-in-out**（`Smooth Molding`）。**禁止 bounce/elastic**。
`prefers-reduced-motion` / 系统"移除动画"开启时时长归 0（状态仍要变，只是不插值）。

### 3.1 版式硬规则（本轮"文字遮挡"的根因都在这里）

- **带开关的行**：说明文字**落在开关下方**并吃满整列，不允许与开关同高横向穿插。
  旧版把说明文字画在标题下 22px、开关画在行首 +2..+28，长文案（"Debug 模式"）被开关切掉半句。
- **分栏页（设置）**：两列各自限宽（`SET_COL_W=288`），每列文字都必须走 `text_col(..., max_w)`；
  单列纵向流 + 硬编码 Y 常量 = 只要有一行文案变长就撞下一块。
- **凸台/卡片不得探出内容裁剪区**：卡片左缘一旦越过 `nav_w`，LG 阴影（外溢 ≈21 逻辑 px）
  会被 `CreateRectRgn` 切成一条硬直线。
- **圆角矩形上的软阴影不能贴边收尾**：元素之间必须留出该档阴影的 `margin` 呼吸空间。
- 极小的状态点（≤6px）**不配阴影**：软阴影的角块比它本身还大，画出来是个方块。

## 4. 排版

- 字体：跟随系统 UI 字体（Windows 取 `lfMessageFont`，Android 用 `FontFamily.Default`）。
  **不引入 Web 字体**：两端体积与离线可用性都不允许，且中文没有合适的免费 display 字面。
- 字号阶（逻辑 px）：`20 页面标题 / 15 卡片标题 / 13.5 正文 / 12 说明 / 11 辅助`。
  层级靠**字重 + 颜色 + 间距**拉开，不靠字号乱跳。
- 指纹、IP、速率这类**机器标识**用等宽（`Consolas` / `monospace`），并加 1px 字距——
  这是本套界面唯一"显示体"，是它自己的小记忆点。
- 行宽上限 65 字符；说明文字不做大段。

## 5. 标志元素：链路槽（Channel Bar）

一条**刻进面板的凹槽**，左右各一个设备凸台（左=本机，右=对端），槽内是链路本身。

```
┌────────────────────────────────────────────────────────┐
│  ╭────╮                                        ╭────╮  │
│  │ ▭  │  ━━━━━━━━━━ 柔光桥 ━━━━━━━━━━  │ ▭  │  │   ← sink.lg 凹槽
│  ╰─📱─╯                                        ╰─💻─╯  │
│   手机        BLE 已连通 · TCP 通道已就绪 · 236 KB/s     │
└────────────────────────────────────────────────────────┘
```

状态语义（**只用形状与明暗表达，不单靠颜色**——无障碍硬要求）：

| 状态 | 槽 | 桥 | 两端凸台 |
|---|---|---|---|
| 未发现设备 | 空凹槽 | 无 | 两端都凸起、图标 `text.disabled` |
| BLE 连接中 | 凹槽 | 半透明桥**呼吸**（reduced-motion 时改为静态 50%） | 本机凸起、对端凸起但描柔光 |
| BLE 已连通 | 凹槽 | 凸起光桥铺满 **40%** | 两端凸起，文字 `state.ok` |
| TCP 已建立 | 凹槽 | 光桥**填满**并微微浮出槽面 | 两端与桥连成一体（同一凸起） |
| 断开 / 故障 | 凹槽 | 桥**断成两截**、中间留缝 | 对端凸台转 `sink`（塌下去）+ `state.err` 文字 |

实现要求：Windows 端这条桥的两端必须是**真高斯柔光**（§6 的软阴影层），
否则"光"会变成一根硬色条，整个隐喻塌掉。安卓端同理。

## 6. 渲染栈映射（技术约束）

### 6.1 Windows：纯 GDI 上做真高斯

实现见 `Platforms/Windows/src/softui.rs`，四个坑都是真机上踩出来的：

1. **蒙版**：对目标圆角矩形解析式生成 alpha 覆盖（`coverage()`：直边也要算距离，
   用 `abs()` + `r+0.5-d` 羽化；写成 `max(0,…)` 会让直边段覆盖恒为 0），
   再用 **3 次可分离盒式模糊**逼近高斯（滑窗 O(n)，边缘必须**钳制**而不是补零，补零会在边界犁出一条暗沟）。
2. **精灵尺寸**：`margin = |offset| + 3×blur + 6`。余量小于 6 会在数组边缘留下非零覆盖 → 一条直缝
   （下限由 `softui::tests::light_is_always_upper_left` 钉死）。
3. **9-slice 拼接**：`cut = margin + radius`；四角原样、四边单向拉伸（源/目标中区宽度都等于
   `w-2·radius`，1:1 不缩）。**右/下角块的原点是 `r-radius` / `b-radius`，不是 `r-margin`**——
   用 margin 定位会让角块与直边错位，宽面上切出一道可见的竖直缝。
   半径必须在**建精灵之前**夹好（`min((w-2)/2, (h-2)/2)`），在 blit 里二次夹取同样会错位。
4. **边缘 alpha 用斜坡不用硬阈值**：精灵是"阴影已与底色合成"后的不透明块，
   若在 `touched>0.05` 处从 1 跳到 0，大片平坦底色上就是一条直边（旧版卡片顶部那道白边即此）。
   现取 `a = (touched-0.01)/0.05` 夹到 0..1。

缓存：`thread_local!` 里的 9-slice 精灵表，**双道闸**——条目 ≤128 且字节 ≤6 MB（`CACHE_BUDGET`），
超预算从最旧开始淘汰但**至少留一条**（当前帧在用的那块被挤掉 = 控件消失）。
字节闸是必需的：缓存键含 `w/h`，单条大小随元素面积长，只按条数封顶时
"拖窗口改尺寸"会让 WorkingSet 从 33MB 一路涨到 62MB（实测 24 次改尺寸）。
`Drop` 时先 `SelectObject` 还原旧 GDI 对象再 `DeleteObject/DeleteDC`。

实测成本（同一台机器，旧版 = `b9b55f9`）：空闲 27.1 → 33.5 MB（+25%），
遍历 7 页后 34.0 MB，GDI 句柄 46 → 49；有动画的页面上 CPU 单核 12.0% → 18.6%
（当时记为待办：限制失效区 / 脉冲降频 / 页面级合成缓存）。

**为什么不用 Direct2D**：当时 `d2d` feature 只是个创建工厂就丢弃的空壳，切 D2D 等于换渲染栈并引入
COM/设备丢失/生命周期三座山，在交付窗口内属于拿稳定换不确定性。GDI 这条路能把真高斯做出来，
且已经有 DPI/字体/主题的正确基础设施。（后来这个空壳 feature 连同 `static mut` 一起被删掉，
交付版只有一条 GDI 渲染路径。）

### 6.2 Android：Compose

实现见 `Platforms/Android/app/src/main/java/com/linkx/app/ui/Neu.kt`。

- **不用 `BlurEffect`**（原计划"API 31+ 走高斯、低版本回退"已作废）：minSdk=26，
  两套渲染路径在低版本上必然与 Windows 端长得不一样，而"两端一致"是硬要求。
  改为**分层叠加**：外阴影 20 层递减 alpha 的圆角矩形（`(1-t)²` 衰减），
  内阴影 16 层「本体 与 本体沿光向位移 sᵢ 的本体」的 **even-odd 差集**（贴边一圈，逐层加宽 →
  边缘最深、向内衰减），再 `clipPath` 裁进形状。
  层间扩散增量必须 <1px，否则真机上会看到一圈圈"洋葱纹"（10 层版本就是这个毛病）。
- 组件清单（与语义一一对应）：`NeuCard`（凸起卡片）`NeuPanel`（凹陷分区底板）
  `NeuButton` `NeuSwitch` `NeuField` `NeuSegmented` `NeuProgress`
  `NeuChannelBar` + `DevicePip`（标志元素）`NeuNavRail` + `NeuNavItem`（底部导航）。
  状态色卡（SAS 比对 / 身份变化）用 `NeuCard(fill = pal.tint(信号色, 0.14))`，
  不整块涂强调色。
- 主题：`LinkXTheme.kt` 的 colorScheme 就是新拟物 token（`background=base`、`surface=raised`、
  `primary=accent.text`、`secondary=ok`、`error=err`）；阴影色不从 colorScheme 猜，
  由 `neuPalette()` 单独给，保证与 `theme.rs` 逐值对齐。

### 6.3 图标（两端共用几何）

- **单一真源**：每个图标在 **24×24 网格**上定义一次（内容留 2px 安全边，画在 2..22），
  Windows 用 GDI 折线/圆弧绘制（`icons.rs`），Android 落成 `drawable/ic_*.xml`，**坐标完全一致**；
- 统一 **2px 描边、圆头线帽、圆角拐接**：Windows 侧改用
  `CreatePen(PS_GEOMETRIC | PS_ENDCAP_ROUND | PS_JOIN_ROUND, …)`——这一条就能消掉大部分"手搓感"；
- 描边宽度随尺寸缩放但**最小 1.5px**，小于 16px 的图标不减笔（否则灰底上会断）；
- 图标一律**单色描边**（跟随 `text.*` / `accent.text`），禁止双色/填充混用，
  新拟物里"凸起"由阴影负责，不由图标负责；
- 词表（对齐 iconfont / Remix 的线性语言）：
  `link · bell · clipboard · folder · settings · play · blocks · phone · pc · upload · download · copy`。
- **设置图标不用齿轮**：试过"中心环 + 8 根径向齿"和"齿根压在环上"两版，20dp 上都读成
  太阳/亮度而不是齿轮。现用**三根推杆 + 旋钮**（Material `tune` 一类，杆在旋钮处断开），
  任何尺寸都读得出"可调"。
- **手机图标**只留机身 + home 条两笔，机身宽 14（旧版过窄 + 带听筒线，读成一个椭圆"0"）。

## 7. 自检清单（交付前逐条过）

- [ ] 背景是 `#e0e5ec`（或暗色变体），无纯黑/纯白
- [ ] 每个阴影都是"左上亮 + 右下暗"双源，模糊半径 = 2×偏移
- [ ] 按钮 hover 阴影**变小**、active **转 inset**，全程无位移
- [ ] 输入框 focus 时内阴影**变浅**
- [ ] 圆角 ≥10，且同屏不超过相邻两档
- [ ] 过渡 300ms ease-in-out，无 bounce，有 reduced-motion 分支
- [ ] 正文/说明文字对比度 ≥4.5:1（**由单测锁死**：`theme::tests::palette_contrast`）
- [ ] 状态不只靠颜色：凹凸/形状也能读出来
- [ ] 两端同一 token、同一图标几何、同一状态语义
